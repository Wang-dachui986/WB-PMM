# 局域网访问修复（2026-11-17，Mac 1.0.12 / Windows 1.0.17）

## 现象

Mac 开启局域网后，Windows 电脑调用 Mac 的局域网地址失败，此前可以使用。Mac 和 Windows 都可能作为对外提供 API 的主机。

## 排查结论

- Mac 网关的放行逻辑自 2026-10-08 起没有变化；在 Mac 上以本机局域网 IP 访问 `/v1/models` 返回 200，`scripts/verify-lan-runtime.py` 全部通过。没有发现 Mac 端代码回退。
- Mac 的 Wi-Fi 使用私有（轮换）MAC 地址，IP 由路由器 DHCP 分配。地址轮换后路由器可能分配新 IP，客户端里保存的旧地址随即失效，表现为“以前能用、现在不行”。这一点无法在本机直接证实，需要在 Windows 端核对所填地址。
- 网关只接受私有 IPv4 来源。用电脑名访问时如果走 IPv6（同网段的全局或链路本地地址），会被误判为非局域网并返回 403。
- 软件没有任何方式显示“对方的请求有没有到达本机”，无法区分地址错误、密钥错误和被拒绝。
- Windows 安装器与应用以普通用户运行，代码中没有防火墙放行逻辑；Windows 作为主机时，其他设备很可能被 Windows 防火墙拦截，若用户曾在系统弹窗中点取消，还会留下阻止规则。

## 修改

1. **电脑名地址**：Mac 与 Windows 的局域网地址列表第一行显示 `http://<电脑名>.local:<端口>/v1`，IP 变化后仍有效；后面列出私有 IPv4。Windows 把有默认网关的网卡排在前面，减少虚拟网卡地址的干扰。电脑名不是合法 DNS 标签（含中文、下划线等）时不显示该行。
2. **来源判定**（gateway `desktop_lan.go`）：在原有私有 IPv4 之外，接受 IPv4/IPv6 链路本地地址、IPv6 私有地址（fc00::/7），以及与本机活动网卡处于同一网段的地址（含同一 /64 的 IPv6）。回环、点对点（代理 TUN、VPN）网卡不参与判定；过宽的掩码（IPv4 短于 /16、IPv6 短于 /48）被忽略。开放接口仍只有 `GET/HEAD /v1/models` 与三种推理接口，并照旧校验 API Key。
3. **局域网请求记录**：网关在内存中保留其他设备最近 30 次请求（时间、来源 IP、接口、状态与结果分类），新增仅本机可读的 `GET /v1/lan-access`；面板 `GET /api/lan-access` 经桌面会话转发；“API 与模型 → 局域网访问”显示“最近的局域网请求”。拒绝响应的提示文字区分“来源不在局域网”和“接口仅限本机”。
4. **Windows 防火墙**：开启局域网且 API 启动后，读取 `wb2api.exe` 的入站规则（无需管理员）。缺少适用于当前网络的放行规则或存在阻止规则时，询问用户；确认后通过 UAC 删除该程序旧的入站规则，添加一条规则：入站 TCP、仅此程序、仅本地子网、仅专用与域网络。当前网络为“公用网络”时提示改为“专用网络”并可打开系统设置。拒绝后本次运行不再询问。
