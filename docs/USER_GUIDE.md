# WB-PMM 使用指南

本指南以 Mac 为例；Windows 的菜单栏对应系统托盘，安装和数据路径见 [Windows 说明](../windows/README.md)。两端打开桌面应用均直接进入控制台，无需额外注册管理账号。

## 1. 安装与首次打开

WB-PMM 1.0.11 支持 macOS 14+ 的 Apple Silicon Mac。取得 `WB-PMM-1.0.11-macos-arm64.pkg` 后双击，按系统安装器提示安装并在需要时输入管理员密码。安装位置固定为 `/Applications/WB-PMM.app`；已有同名版本会被整体替换，不需拖拽。安装会正常退出运行中的旧版，完成后从“应用程序”或 Dock 启动。用户可在 [GitHub Releases](https://github.com/Wang-dachui986/WB-PMM/releases) 查看已发布安装包。安装包已内置管理面板和网关，普通使用无需安装 Go、Node.js、Docker 或 Redis。

此版本的 App 使用临时签名，PKG 尚无 Developer ID Installer 签名，两者均未公证。若系统提示无法验证开发者，请确认文件确实来自上述发布页；尝试打开一次后，在“系统设置 → 隐私与安全性”中找到针对该 App 的“仍要打开”，再确认“打开”。[Apple 官方说明](https://support.apple.com/zh-cn/102445)有图文步骤。若系统报告 App 已损坏或有恶意软件，请停止打开并重新核对发布文件；不要关闭全局安全检查。

首次进入控制台时，按向导检查本机准备状态和端口。账号可以在向导中添加，也可以稍后在“账号管理 → 添加账号”操作。没有可用账号时 API 进程仍可能运行，但无法完成模型调用。

首次设置以悬浮框显示在当前操作旁，依次说明本机准备、账号授权、启动 API、复制地址、复制密钥和选择模型。高亮按钮仍可直接点击，浮层会随页面滚动及窗口大小调整位置。点击“跳过”或按 Esc 可收起；完成或跳过后不再自动弹出，可在仪表盘右上角点击“使用引导”重新打开。跳过不会开启自动启动，也不表示账号或模型已经通过测试。已完成旧版首次设置的用户可手动打开新引导。

## 2. 添加账号并启动 API

1. 在“添加账号”选与你账号相符的区域：国内版或国际版。点击“发起授权”。
2. 点击“打开授权页面”，在系统浏览器完成上游登录与授权。返回应用等待检测；链接过期后重新发起。
3. 显示“凭证已保存”后进入“账号管理”查看状态。若提示尚未保存，按页面提示重试或确认覆盖已有账号。凭证只保存在本机数据目录，重新授权可更新过期凭证。
4. 在窗口顶部服务栏或菜单栏启动 API。启动、停止或重启后，仪表盘会自动刷新网关状态，无需再点“立即刷新”。若提示端口占用，到“网关配置”选择空闲的 1024–65535 端口并保存应用。

### 导入已有 JSON 凭证

在“添加账号”选择导入 JSON，使用系统文件选择器选取本人有权使用的单账号凭证，再核对预览并确认。支持 UTF-8（含 BOM），单文件不超过 1 MiB；不支持 UTF-16、文件链接或账号数组。支持下列两种结构，示例中的值是占位内容：

```json
{"account":{"uid":"YOUR_UID"},"auth":{"accessToken":"YOUR_ACCESS_TOKEN","refreshToken":"YOUR_REFRESH_TOKEN","domain":"codebuddy.cn"}}
```

```json
{"uid":"YOUR_UID","accessToken":"YOUR_ACCESS_TOKEN","refreshToken":"YOUR_REFRESH_TOKEN","domain":"codebuddy.cn"}
```

国内域名支持空值、`copilot.tencent.com`、`codebuddy.cn`、`www.codebuddy.cn`，国际域名支持 `workbuddy.ai`、`www.workbuddy.ai`。未知域名会拒绝；同 UID 覆盖须确认，跨区域覆盖会拒绝。导入只保存已有授权，不能生成或恢复上游令牌；令牌失效请重新授权。凭证导入与供客户端使用的网关 API Key 是两个功能，后者在“API 与模型”复制。

账号页可以查看账号详情、手动签到、重新授权和删除本机凭证。删除后需重新 OAuth 授权才能加入账号池。管理面板使用的登录身份与提供给 API 客户端的 Key 是不同凭据。

本机账号列表与账号池已用 100 个模拟账号验证，不存在 20 个总账号的限制。积分查询按最多 20 个一批执行；账号页可勾选账号后批量删除，确认框列出将删除的账号。仪表盘“剩余积分”旁的“查询全部积分”会读取当前全部账号并分批查询，显示完成进度；结束后统一刷新积分、账号列表和网关状态。失败或缺少凭证的账号不会被当成零积分，部分成功时仅合计成功账号并明确提示覆盖范围。查询中可取消，离开仪表盘也会停止后续批次；如原生应用提示账号维护确认，请按提示操作。账号容量不代表平台允许集中授权或调用，使用范围以上游规则与授权为准。

## 3. 把客户端连到本机

在“API 与模型”点击复制当前 Base URL、完整接口地址、API Key 和完整模型 ID。默认 API 地址如下；改过端口后以应用内显示值为准。

| 协议 | 完整 POST 地址 | SDK Base URL |
| --- | --- | --- |
| OpenAI Chat Completions | `http://127.0.0.1:7863/v1/chat/completions` | `http://127.0.0.1:7863/v1` |
| OpenAI Responses | `http://127.0.0.1:7863/v1/responses` | `http://127.0.0.1:7863/v1` |
| Anthropic Messages | `http://127.0.0.1:7863/v1/messages` | `http://127.0.0.1:7863` |

SDK 若自动拼接接口路径，请填表中的 SDK Base URL；要求填写完整接口地址的客户端则填对应的完整 POST 地址。WorkBuddy 客户端未开启“自定义协议”时用 `/v1` 结尾的 Base URL；开启后用 `/v1/chat/completions` 结尾的完整地址。国内版与国际版都按此开关选择。路径填错或重复拼接通常会得到 404。

OpenAI 接口通过 `Authorization: Bearer <本机 API Key>` 鉴权；Messages 接口可用 `x-api-key: <本机 API Key>`，也可用 Bearer Key。管理面板口令不能代替这个 Key。API 默认仅监听 `127.0.0.1`；局域网共享需主动开启下述开关。不要把 Key 粘贴到公开网页或日志。轮换 Key 后，旧 Key 会失效，需同步更新客户端。

选择模型时复制完整 ID，保留 `global:` 等前缀。模型列表、上下文长度、最大输出 Token 和可选推理强度以当前实际返回的元数据为准；某些模型可能不提供这些字段。这里的上下文数字不是每个账号、每次请求都能达到的保证。一个简短的请求样例可在“API 与模型 → HTTP 请求示例”复制，其中 `YOUR_API_KEY` 是占位符。

“API 与模型 → 本地连通检查”只读取本机状态，不向上游发起模型请求。要验证实际可用性，在“聊天测试”选模型并手动发送消息；该操作可能消耗上游额度。测试页可设置可选的系统提示词、`temperature`（0–2）、最大输出 Token、模型提供的推理强度和流式输出。最大输出只限制回答长度，不增加上下文容量。

“请求统计”只汇总当前网关进程的数据；停止或重启 API 后从零开始，不能作为跨运行账单。上游未返回用量的请求不会凭空补成已观测 Token。

### 同一 Wi-Fi / 局域网接入（1.0.1 起）

1. 在 Mac 的“网关配置”勾选“允许局域网访问”，点击“保存并应用”。开关默认关闭；运行中的网关会通过现有配置流程重新启动，正在进行的请求需先结束。
2. 启动 API。在仪表盘或“API 与模型”找到“局域网地址”，复制该地址及同一个 API Key。其他设备不要填写 `127.0.0.1`，它表示那台设备自己；也不要填写 `0.0.0.0`，它只是网关的监听配置。
3. 例如应用显示 `http://192.168.1.23:7863/v1`，其他设备的 OpenAI 客户端就填写这个 Base URL。完整端点是在该地址后追加 `/chat/completions` 或 `/responses`；Anthropic SDK 的 Base URL 通常去掉末尾 `/v1`，完整 Messages 端点为 `http://192.168.1.23:7863/v1/messages`。模型 ID 与本机相同。
4. 在另一台设备读取带 Key 的 `/v1/models` 可检查连通性；发送聊天请求才验证模型实际调用，并可能消耗积分。Mac 需要保持运行、联网且 API 已启动，休眠或完全退出应用会中断服务。

此版本支持私有 IPv4 地址（`10.*`、`172.16.*` 至 `172.31.*`、`192.168.*`）。多个网卡时选与客户端处于同一局域网的地址；更换 Wi-Fi 或重新分配 IP 后需复制新地址；仪表盘与“API 与模型”页在可见时每 15 秒刷新地址，重新回到页面也会更新。停止状态下不会显示为可连接。

连接失败时，先检查 API 状态和地址；按 macOS 防火墙提示允许内置网关接收入站连接，检查路由器是否开启“访客网络 / AP 隔离”，以及客户端代理是否绕过局域网。无需关闭整个防火墙，也无需设置公网端口转发。仅在可信网络使用：当前使用 HTTP，不提供传输加密；拥有 Key 的设备可以调用账号池并消耗积分。关闭局域网开关并保存后恢复仅本机访问。

开放范围仅包括模型列表与三种推理接口。控制台、账号状态、请求统计、健康检查及管理操作仍只允许本机访问；从其他设备打开 `/healthz` 得到 403 属于预期行为。局域网开关不改变账号凭证的保存位置。

## 4. 协议支持范围

Chat Completions、Responses 和 Messages 共用同一账号池、本机 Key 和端口。支持常见文本请求、非流式回复、SSE 流式回复、函数工具调用及工具结果回传；图片输入可转换，但能否识图取决于上游模型。

多轮对话须由客户端在每轮携带完整历史。Responses 使用无状态模式，不支持 `previous_response_id`、服务端存储、后台任务或平台内置工具；Messages 不支持 Anthropic 扩展思考、签名思考块、平台内置工具、图片工具结果及缓存控制。未支持的请求字段会返回错误。兼容层不能保证所有 Agent 的扩展都可直接使用。实际额度和计费由上游决定；上游没有返回用量时，页面的统计可能显示未知或协议要求的占位值，占位 `0` 不代表免费。

## 5. 自动签到与后台运行

在“网关配置 → 自动签到领积分”打开开关，填写本机时区的整点小时（0–23，用逗号分隔，默认 `9, 21`），点击“保存并应用”。排程只在 API 服务运行期间执行；已禁用、无可用凭证的账号和国际版账号会跳过。签到会按需刷新令牌并查询积分，上游实际发放结果可能变化。停止 API 或完全退出 App 期间不会执行；重启后从后续设定时间继续。

关闭主窗口，应用与已启动的 API 会留在 macOS 菜单栏。菜单栏可打开主窗口、启停或重启 API、复制地址以及“完全退出”；完全退出会停止内置服务。“应用设置”中有两个独立选项：手动打开应用时启动 API，以及登录 macOS 后自动打开应用并启动 API。两者默认关闭。第二项需在“应用设置”点击“保存偏好”；若显示等待系统批准，到 macOS“系统设置 → 通用 → 登录项”允许后回到应用刷新状态。请先把 App 放在固定安装位置再启用登录项。登录启动指用户登录后启动，并非系统启动前的后台服务。

## 6. 更新、备份与卸载

- **更新**：从发布页阅读新版本说明，先结束正在进行的模型请求，再运行新版 PKG。安装器会请求旧版正常退出，无法退出时会中止安装；始终整体替换 `/Applications/WB-PMM.app`，不会跟随旧版位置安装到 DMG 或临时目录。账号与配置保存在 App 外，会继续保留。
- **Dock 与旧安装盘**：安装器将当前登录用户 Dock 中固定或最近使用的 WB-PMM 图标指向 `/Applications/WB-PMM.app`，保留其他图标和排列；未固定时不会额外添加图标。Dock 可能短暂刷新。安装结束后弹出旧 DMG，从“应用程序”或修正后的 Dock 图标打开。安装器不会删除其他目录里的旧 App 副本。无桌面用户登录的部署不会修改 Dock。
- **备份**：在“应用设置”点击“打开数据目录”。目录 `~/Library/Application Support/WorkBuddy2APIDesktop/` 含 `auths/` 账号凭证、`gateway-config.json`、`panel-config.json` 和备份文件，应像密码一样保护，不上传到公开仓库。日志位于 `~/Library/Logs/WorkBuddy2APIDesktop/`，应用内可直接打开。
- **卸载**：如已启用登录项，先在“应用设置”关闭并保存；从菜单栏“完全退出”，再把“应用程序”里的 App 移到废纸篓。卸载 App 不会自动删除账号、配置或日志。只有确认不再需要数据并完成备份后，才在 Finder 中手动处理上述目录。

## 7. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| API 返回 503 | 在服务栏确认 API 已启动，再看“账号管理”是否有可用账号。`/healthz` 的 503 也可能表示进程仍在运行，但当前账号池没有可服务账号或已达到并发上限；查看“日志与诊断”中的具体原因。 |
| 客户端返回 404 | 核对请求方法与完整路径；WorkBuddy 的“自定义协议”开关决定应填 `/v1` 还是 `/v1/chat/completions`。Anthropic SDK 自动拼接 `/v1/messages` 时应填服务根地址，避免重复路径。 |
| 提示额度不足或限流 | 查看账号详情和上游返回的信息；积分及限流由上游控制。切换账号或等待恢复是否有效取决于上游，应用不保证可用额度。 |
| 模型列表为空或模型不可用 | 确认账号区域、授权状态和 API 状态；在“API 与模型”重新读取，复制当前完整模型 ID。模型可用性可能随上游变化。 |
| 关闭窗口后仍能访问 API | 这是菜单栏运行方式。需要停止时从菜单栏点击“停止 API 服务”或“完全退出”。 |
| 登录后没有自动启动 | 检查“应用设置”的登录项状态与 macOS“系统设置 → 通用 → 登录项”，确认 App 未被移动。登录项在用户登录后触发。 |

出现故障时，先在“日志与诊断”查看本机服务和最近错误。共享诊断前检查并遮盖账号、Key、Token 等敏感信息。
