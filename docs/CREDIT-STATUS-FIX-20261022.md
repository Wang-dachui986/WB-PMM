# 积分认证状态显示修复（2026-10-22）

## 原因与修复

账号池 healthy 只代表候选调度状态；本地 expiresAt 只代表文件记录的过期时间。此前界面将两者表述为“可用/全部有效”，且批量积分失败没有进入账号视图，造成与失败列表矛盾。

- 批量、单次查询失败记录到账号视图：credits_status / credits_error / credits_at；401 标记 auth_rejected，其他错误标记 failed；未查询保持未知。
- 查询失败清除旧观测余额，汇总不再用网关旧余额掩盖查询失败。成功后清除异常。
- 重新授权或导入成功清空旧查询记录，需重新查询验证。
- 仪表盘“候选/已载入”与“积分认证”分开表达，不再显示“全部有效”；401 红色、其他失败/未验证黄色、查询成功绿色；账号列表与异常列表显示认证结果。
- 不根据积分接口失败自动禁用聊天账号；聊天调用是否可用需独立证据。

## 真实只读检查

选取一个查询成功账号和两个查询失败账号进行对照（公开文档已移除个人昵称和 UID）。此前旧 /v2/billing/meter/get-user-resource 对照为 200/code0、401、401；本次新版 www.workbuddy.cn/billing/meter/get-user-resource-summary 同样为 200/code0、401、401。失败账号新版接口返回 401 HTML 鉴权拒绝页，而非余额不足数据。

可以确认当前积分服务拒绝被抽查旧凭证；不能确认上游撤销会话的具体政策或判定所有19账号相同，更不能推断账号被封或聊天不可用。没有额外发送模型请求，没有批量刷新或修改用户凭证。

## 验证

两端 Go ops/upstream 回归，TypeScript/Vite 构建，仪表盘100账号分批/取消回归，以及1成功19拒绝与全未查询的页面渲染回归。安装包仅完成构建与包检查，未执行覆盖安装；Windows仍需实机验收。Mac包使用临时本地签名且未公证。
