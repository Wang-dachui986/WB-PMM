# WB-PMM Windows 10/11 x64

Windows migration from the frozen macOS 1.0.3 baseline. This directory is the Windows implementation; macOS source and release remain frozen separately.

## 安装与升级

运行 `WB-PMM-Setup-1.0.10-x64.exe`（开发候选文件名额外带 `-compile-check`）。首次安装可在目录选择页选择有写入权限的本地文件夹，默认 `%LOCALAPPDATA%\Programs\WB-PMM`，安装结束后在开始菜单和桌面各生成一个 WB-PMM 快捷方式，升级更新原快捷方式，卸载时移除。后续升级默认读取上次选择的位置，请求运行中的应用正常退出后原地覆盖。如需换盘，先卸载再选择新目录安装；账号数据仍保留。上一版若在快捷方式身份步骤失败且尚未完成注册，可直接运行新版安装器选择位置。若退出失败，安装中止，请完成正在执行的任务后重试。不要在运行中手工替换程序文件。

账号、网关配置、偏好和安全日志放在 `%LOCALAPPDATA%\WB-PMM`，与安装目录分开。覆盖升级和卸载保留这份数据；卸载后重新安装可继续使用。不要把数据目录上传到仓库或发给别人。

安装包包含 .NET 运行组件，无需单独安装 .NET。界面使用 Microsoft WebView2 Runtime：缺少时安装向导通过微软官方引导程序联网安装，失败则停止并提示。已有运行时不重复安装；离线电脑须提前安装 WebView2 Runtime。流程依据 [微软部署说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。应用运行不需要管理员权限；局域网访问如被 Windows 防火墙阻止，按验收说明为私有网络放行。

当前仅面向 Intel/AMD x64，Windows 10 22H2 / Windows 11。尚未完成 Windows 实机验收，不能把交叉编译通过当作可发布结论。Windows 10 系统安全支持状态由微软的版本与授权政策决定。

## 基本使用

1. 从开始菜单打开 WB-PMM，按浮动引导添加国内版或国际版账号；授权在系统浏览器完成。
2. 启动 API，仪表盘自动更新运行状态。可在剩余积分处查询全部账号积分；未知余额不会算作零。
3. 复制 API 地址和密钥到客户端。本机默认 Base URL 为 `http://127.0.0.1:7863/v1`。
4. 如客户端要求完整端点，按协议填写 `/v1/chat/completions`、`/v1/responses` 或 `/v1/messages`。WorkBuddy 是否需要完整对话端点取决于「自定义协议」选项，不按国内/国际区分。
5. 关闭主窗口会继续在通知区域后台运行；点托盘图标重新打开，选择「完全退出」停止应用与受管服务。
6. 「应用设置」可分别控制随应用启动 API 和登录 Windows 后启动。首次安装不会自行开启登录启动。
7. 「网关配置」开启局域网并保存应用后，同一网络的设备使用所显示的局域网地址和同一个 API 密钥。管理面板保持仅本机可访问；不要向互联网开放端口。

自动签到在 API 运行期间按本机时区设定的小时执行，仅支持国内账号。100 个账号容量、批量余额查询、模型/推理/上下文设置、聊天测试、统计、日志与诊断使用现有业务页面。模型实际能力仍以上游返回为准，填写 1M 不会扩大上游的硬限制。

## 构建

需要 .NET 10 SDK、Go 1.22 或更高版本（建议使用与验证相同的 Go 1.26）、Node.js 22、NSIS 3 Unicode。

Windows PowerShell：

```powershell
.\windows\build.ps1
.\windows\package.ps1
```

macOS/Linux 维护者可用 `DOTNET=/path/to/dotnet GO=/path/to/go bash windows/build-cross.sh` 交叉编译，再使用 NSIS 编译安装包。Windows 系统能力仍须到实机验证。

## Windows 1.0.4 安装修正

- 新增安装目录选择页；升级记住原目录，卸载按实际目录工作。
- 首次安装选择空文件夹；能够识别并修复上次失败留下的完整 WB-PMM 程序目录，拒绝覆盖其他非空目录。
- 开始菜单快捷方式创建与附加任务栏标识分开校验；标识由自包含 x64 应用通过 Windows COM 写入并重新读取验证，不再调用 PowerShell 动态编译。
- 标识失败显示安全错误代码，保留可用程序和普通快捷方式，不再把此辅助步骤当作整包失败。
- Windows COM 写入、目录选择和覆盖升级需实机复测；本机仅做编译和离线检查。

## Windows 1.0.5 账号授权修正

- 修正维护许可的到期时间序列化：以 UTC `Z` 格式发送，兼容 Go 面板；旧版数字时区被 JSON 转义后遭拒绝，会触发保护性关闭面板。
- 维护前 API 未启动时，维护结束恢复“已停止”，释放操作锁。
- 桌面版发起授权后自动打开系统浏览器；打开失败保留当前会话，可点“打开授权页面”重试。
- 本地真实 C# 客户端与 Go 面板已验证许可申请/释放及面板存活，没有请求真实 OAuth 或模型；Windows 浏览器登录、凭证保存仍需在实机确认。

## Windows 1.0.6 桌面快捷方式

安装默认在当前用户桌面创建 WB-PMM 快捷方式，图标和任务栏身份与开始菜单一致；使用 Windows 桌面目录设置，支持移动或重定向后的桌面路径。覆盖升级更新原快捷方式，卸载移除该快捷方式并保留账号和配置。

## Windows 1.0.9 首次安装目录修正

修正首次安装时默认目录或新建目录尚不存在而被误判的问题：路径规范化改用 Windows API，校验通过后才创建目录。仍检查磁盘根目录、系统目录、账号数据目录、链接目录和无关非空目录，不需要预先手动创建安装文件夹。保留 1.0.6 的桌面快捷方式功能。

`windows/verify.ps1` 增加直接调用同一 NSIS 路径宏的回归检查，覆盖不存在的多级目录、中文与空格、`..` 规范化、已有目录及空路径拒绝。该检查和安装流程须在 Windows 上执行；本机交叉编译不替代实机验收。

## 1.0.10 Token 统计

左侧「Token 统计」支持日、周、月、年度及模型筛选，可切换方块热力图、扇形图、柱状图、曲线图。历史保留最近 400 天，仅累计上游实际返回的用量；升级前未保存的数据无法补回。完整说明见安装目录的 TOKEN-STATISTICS.md。
